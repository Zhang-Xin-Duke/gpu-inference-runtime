## Purpose and current implementation

This is a C++20/PyTorch inference infrastructure portfolio project. The native scheduler handles bounded admission, compatible batching and queue deadlines. PyTorch owns tensor packing, reusable staging slots, CUDA streams/events and result lifetime. Dense MLP and variable-length sequence adapters are implemented.

The distributed extension uses complete model replicas: a CPU router checks weight fingerprints and routes binary HTTP requests to workers with less outstanding work. It implements bounded pending work, temporary failure cooldown and one alternate-replica retry. Every worker keeps its own batching queue. Remote work can continue after timeout; retries can duplicate stateless computation.

```bash

python scripts/extended_matrix.py --device cuda --kind dense --output-dir results/rtx5090/dense --cell-seconds 15 --soak-seconds 300
```

These matrices vary offered load (100–8,000 req/s), execution mode, batch size, slot count, model/sample size or sequence lengths, and include a five-minute soak. Inspect resource usage and test failures between phases. The load generator uses a separate process, a bounded descriptor queue, a seeded input catalog and fixed-memory latency histograms with approximately 1% relative bin resolution.
